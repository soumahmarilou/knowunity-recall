# Scorecard 02 — Home chat, Study plan, Mode selection, Free Recall Challenge – Intro

Scope: identical to `eval/scorecard-01.md` — `/` (Home chat), `/study-plan`, `/recall` (Mode selection), `/recall/free-recall-challenge` (Intro/launch). All four rendered at 390px, dark mode. Scored against `eval/rubric.md`. Run against the current working tree, which includes an uncommitted follow-up pass ("Fix scorecard-01 findings: real pressed states, touch targets, token compliance") on top of scorecard-01's `33e7e2a`.

Method: (1) every state of each screen was rendered and screenshotted via Playwright (default, typed/empty, tab switches, pressed via `mouse.down()`+move-away-before-release, long/custom subject, a fresh no-history context for the Close button), diffed by SHA-256 of the PNG bytes and by live computed-style comparison to catch states that should differ but don't. (2) Four critics — critic-system, critic-craft, critic-ux, critic-ambition — each ran independently in isolated contexts, given only these four screens, `eval/rubric.md`, and their own dimensions; none saw another critic's output, and none was told what scorecard-01 found or what had since been "fixed" — they each did a genuine first-look pass on the live app.

## Overall score: 5.33 / 10 (uncapped — all four hard gates pass as of this update)

Computed weighted average: `Σ(score × weight) / Σ(weight)` = `(7×3 + 6×3 + 4×3 + 3×3 + 8×2 + 4×1) / 15` = `80 / 15` = **5.33**.

At the time the four critics ran their independent review, one of four hard gates failed — **no silently-identical states** — which would have capped the eval at 5/10 regardless of dimension scores (see scorecard-01, where the same cap applied and *didn't* move the number, since the raw average there was already under 5). That specific gate failure (Study plan's current-step button and the bottom nav bar both missing a pressed state entirely) was fixed directly in this same session immediately after the review — see the hard-gate table below for exactly what changed and how it was re-verified live. With that fix in place, all four hard gates now pass, so **no cap applies** and the overall score is the raw weighted average: **5.33**.

**Caveat, unchanged from before:** the six dimension scores above are frozen at what the four critics independently found *before* the fix — they were not re-run against the post-fix code, since re-scoring a dimension is each critic's own job, not something to self-assign here. Craft's 4/10 in particular was assigned partly *because of* the now-fixed gate failure ("the app's persistent chrome... gives zero tactile feedback"), so a real re-review of Craft (and possibly Structure) would likely move those numbers up, which would move the weighted average above 5.33 too. Treat 5.33 as a floor, not a fresh re-score — it's the old dimension scores with the gate cap correctly lifted, not a new evaluation of the fixed code.

## Findings, ranked by severity, with evidence

**1. Mode selection's Close button still dead-ends at `about:blank` for a student with no prior in-app history — unfixed, hard-constraint violation.**
`src/app/recall/ModeSelectionContent.tsx:50` — `onLeftClick={() => router.back()}`, unchanged since scorecard-01. Reproduced independently twice this round: the phase-1 pass (fresh Playwright context, `goto` as the first action, tap Close → `about:blank`) and critic-ux (same setup, `window.history.length === 2`, the genuine no-history floor, tap Close → `about:blank`, empty body). critic-ux notes this is also the realistic first-encounter path — a deep link, QR code, or push notification lands exactly here with no history to go back to. Confirmed the fix is narrow: with real in-app history (Home → Recall exercice → Mode selection), Close correctly resolves. *Fix, unchanged from scorecard-01: `onLeftClick={() => router.push(entry === "study-plan" ? "/study-plan" : "/")}`, matching the pattern the mode Intro screens already use.*

**2. That fix, if copied verbatim from the Intro screens, would import a second, subtler bug — Close silently drops `entry` on every mode's own Intro, not just Mode selection.**
Found independently by critic-system (via live click-through: Study plan → Mode selection → FRC Intro → Close, with `entry=study-plan` present the whole way → lands on `/`, not `/study-plan`) and by critic-ux (same defect, isolated to FRC Intro: `IntroContent.tsx:42`, `router.push("/")` hardcoded, while the same file threads `entry` correctly into its own Start button two lines later). `src/app/recall/guided-reflection/IntroContent.tsx` and `src/app/recall/concept-questions/IntroContent.tsx` share the identical hardcoded pattern. This isn't a trap (Home is always reachable), but it's a real coherence seam: the same visual Close affordance means two different things depending which screen it's on, and a student who tapped in from Study plan loses that context the moment they view any mode's Intro and back out. *Fix: apply the same `entry`-aware destination to all four Close buttons (Mode selection + the three mode Intros), not just Mode selection.*

**3. Hard gate: two components failed "no silently-identical pressed state" at review time — fixed post-review, see hard-gate table.**
Study plan's current-lesson-step button (unfixed carryover from scorecard-01) and the bottom nav bar (`NavigationButton`, newly found this round — not in scorecard-01's three named components, present on every screen with a nav bar). Both confirmed via two independent methods (SHA-256 screenshot hash + live computed-style diff) showing zero visual change between default and `:active`. Both components' CSS had no `:active`/`.pressed` rule whatsoever — the same category of bug ActivityCard and SuperlistItem had before this round's fix, just not caught by whatever fixed those two. **Fixed in this same session, after the critics' review**: see the hard-gate table for the exact change and live re-verification.

**4. Long, unbreakable subject text still overflows the 390px frame — unfixed.**
Reproduced independently by the phase-1 pass (`scrollWidth` 793px against a long subject) and by critic-craft (`scrollWidth` 869px with a different long subject string, "Pneumonoultramicroscopicsilicovolcanoconiosis…"). `TextBlock.module.css` is untouched since scorecard-01 — still `width: fit-content` on `.textBlock`, no `overflow-wrap`/`word-break` on `.title`, confirmed via `grep -rn "word-break\|overflow-wrap" src/` returning nothing anywhere in the codebase. This is Mode selection's own heading, which takes raw student input directly — a reachable path, not contrived. Note: FRC Intro's heading is hardcoded ("Free Recall Challenge") and never interpolates the subject, so testing overflow there produces a false negative; Mode selection is the only real reproducer in this scope. *Fix, unchanged from scorecard-01: `max-width: 100%; overflow-wrap: break-word;` on `.title`, plus `min-width: 0` on its container.*

**5. FRC Intro's mic-permission ask is never primed before the OS prompt fires.**
critic-ux, checked against voice-ux.md's Principle 3 ("Prime it first with our own screen that explains the value, then let the OS dialog appear"). `src/app/recall/free-recall-challenge/IntroContent.tsx:51-66`'s three benefit rows ("60 seconds to say everything you remember," "Watch your coverage gauge fill up," "Active recall boosts retention by up to 20%") never mention the microphone, that the OS will ask for access, or what happens on decline. A student tapping Start gets the native permission dialog cold, with no framing at all — this is the specific screen voice-ux.md's own checklist names for that priming job. *Fix: add a line of Knowie copy naming the mic explicitly before Start, e.g. "We'll ask to use your mic — you can always switch to typing."*

**6. A structurally identical hero renders with two different gaps on two adjacent screens.**
critic-craft, confirmed via live computed `gap`: Mode selection's `.hero` (`MascotSlot` 2XL excited + `TextBlock` variant L) is `12px` (`--spacing-300`, `recall/page.module.css:32`); FRC Intro's structurally identical hero is `16px` (`--spacing-400`, `free-recall-challenge/page.module.css:24`). Not logged as an intentional deviation in `component-gaps.md`. Guided Reflection and Concept Questions' own Intros both use `--spacing-400` per their code comments, which makes Mode selection's `300` the outlier. *Fix: standardize on `--spacing-400` in `recall/page.module.css`.*

**7. Disclosed component substitutions exist only in inline CSS comments, not cross-logged in `component-gaps.md`.**
critic-system: `BadgeChip.module.css:13-15` (label typography substituted from Figma's literal value, used on Home's AppBar) and `SuperlistItem.module.css:64-66` (descriptor line-height substituted, used on all three Mode selection cards) both document a real deviation at the point of use but never made it into `component-gaps.md`, which the rubric's top band requires for every unavoidable gap. Lower severity than the findings above since the values themselves aren't wrong, just under-disclosed.

**8. Avatar's "Large" size remains an unverified guess, and it's on every in-scope screen.**
Already disclosed in `component-gaps.md` (carried over from before scorecard-01, still unresolved): `spacing-800` (32px) was used as "a reasonable estimate, not a verified Figma binding." critic-system flags this as a residual risk specifically because it renders on both Home's and Study plan's nav bars — every screen in this scope that has a nav bar uses the guessed value. Properly disclosed, so lower severity, but worth re-surfacing since it's unresolved across two scorecards now.

**9. Duplicate, independently-maintained route for what Home and Study plan treat as the same screen.**
critic-craft: `src/app/recall-exercice/page.tsx` is a structural duplicate of `src/app/recall/page.tsx` — Home routes to `/recall-exercice`, Study plan routes to `/recall`, for what is effectively the same Mode-selection-adjacent step. Both render correctly (no Structure cost), but it's two live copies of the same screen with independent CSS, which is exactly the kind of duplication that drifts out of sync over time — `/recall-exercice` was not part of this scorecard's scope, so it wasn't checked against the same rubric bar `/recall` was.

**10. No motion applied to any in-place pressed-state change.**
critic-craft: `grep -rn "transition"` across all four screens and their component dependencies returns nothing. Every pressed state that does work (ActivityCard, SuperlistItem, AppBar icon buttons, Start button, Focus Mode button) snaps instantly rather than following the project's own documented ~150ms opacity rule for in-place changes. Not a rule violation (nothing does the *wrong* kind of motion), just an unclaimed opportunity — lowest severity of the findings above.

**11. Ambition-tier gaps — informational only, not part of the weighted total.**
Study plan's stats row still hand-rolls what `StatBox` already covers and is already proven in a side-by-side pair one screen away (Final Summary). FRC Intro's benefit list still uses flat `IconSlot` + `<p>` rows instead of the colored `SuperlistItem` treatment Mode selection already gives the exact same "icon + title + descriptor" shape one screen earlier. All three in-scope hero moments (Home, Mode selection, FRC Intro) repeat the identical `MascotSlot` `expression="excited"` even though a wider, already-wired expression range (e.g. `determined`, already used live in two processing screens) could differentiate FRC's higher-stakes framing. See critic-ambition's read below.
