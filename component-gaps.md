# Component gaps

A running list of things built inline (from tokens, not a cataloged Storybook component) during a screen build, and which screen each was for. Read before building a new screen — if the same gap shows up a second time, build it as a real component with a story instead of inlining it again.

- ~~**The mic-permission primer card (the "Knowie needs your mic…" confirm card with Allow/Not now) was inlined identically on 4 separate screens**~~ **Resolved** — Guided Reflection's Launched, Concept Questions' Launched, Free Recall Challenge's Launched, and its Aspect-to-revise sub-flow all had byte-identical copies of this card (markup and CSS), and it was never logged here at all until a spec-conformance review caught it — a direct miss of this file's own "flag it, promote on repeat" rule, since nobody had the chance to notice it recurring. Built as a real component per direct instruction (`src/components/MicPermissionPrimer/`, + story), all 4 inline copies replaced. Its `max-width: 280px` is still a raw, un-tokened value (no spacing step lands near 280px) — flagged, not invented, carried over unchanged from the inline version.

- **`TranscriptView` is a wholly new component, not ported from Figma or SPEC.md** — a live "song lyrics"-style scrolling transcript (fade at top/bottom via a `mask-image` gradient, auto-scrolls as text grows), per direct instruction. Needed on every mode's own Recording screen at once (Guided Reflection, Concept Questions, Free Recall Challenge's main loop and its Aspect-to-revise sub-flow), so built as a real component from the start (`src/components/TranscriptView/`, + story) rather than inlined 4 times. `aria-hidden`, not `aria-live` — it updates as often as every ~180ms, which would spam a screen reader if announced. **Updated**: the text it renders now comes from `useSpeechTranscript` (`src/lib/speechTranscript.ts`) — real words via the browser's Web Speech API, a disclosed exception to CLAUDE.md's "no speech-to-text" rule (see that file). `useMockTranscript` (`src/lib/mockTranscript.ts`, scripted filler) is now the fallback for browsers without Web Speech API support, not the primary path.

- **Avatar didn't exist at all** (already flagged in SPEC.md before this build). Needed for **Home chat – Default**'s nav bar. Built as a real component (`src/components/Avatar/`, + story) rather than inlined, per SPEC.md's own build note. Two disclosed substitutions: (1) Figma's instance is `Type=Image`, but no real avatar-image asset or system exists anywhere in this project (and Figma was disconnected, so its actual image fill couldn't even be exported) — renders the `Initials` fallback ("H") instead, a real avatar pattern, not an invented one. (2) The "Large" size's exact pixel value was never confirmed — used `spacing-800` (32px, matching `icon-400`'s value) as a reasonable estimate, not a verified Figma binding.
- **ActivityCard had no way to be tapped.** No `onClick`, rendered a plain `<div>` — despite its own doc comment describing it as a "quick-action entry point." Needed for **Home chat – Default** (the "Recall exercice" card must navigate to `/recall-exercice`). Added an optional `onClick` prop, rendering a real `<button>` when provided — same pattern as `SuperlistItem`'s `showTrailingChevron`. Added the matching button-reset CSS (`border: none`, `cursor: pointer`, `font: inherit`) to `ActivityCard.module.css`, same precedent as `SuperlistItem.module.css`.
- **Seven icons SPEC.md/Figma call for don't exist: `trending-up-01`, `timer-01`, `gauge-01`, `raised-hand-01`, `myai-chat`, `search-md`, `trophy-02`.** (`target-04` was already there.) Needed for **Concept Questions – Intro** (trending-up-01), **Free Recall Challenge – Intro** (trending-up-01/timer-01/gauge-01), and **Home chat – Default** (raised-hand-01, myai-chat, search-md, trophy-02). Not in `Icons.tsx`'s original 24 exports. Built directly as real, cataloged icons (`Icons.tsx` + `Icons.stories.tsx`) rather than inlined per-screen, since icons only ever live in that one shared file anyway — but they're hand-built geometric approximations, not ported from Figma's real vector paths, because the Desktop Bridge plugin was disconnected for every one of these builds (confirmed live, five separate times this session). Anatomy came from each Figma frame's layer *names* where available (stopwatch has a face/hand/pivot/crown/stem; gauge has an arc/needle; trending-up has a line + arrowhead); the four nav/activity icons had no such detail available, just the bare instance name, so those four are closer guesses at a recognizable pictogram (raised hand, chat bubble, magnifying glass, trophy) than the first three. Replace all seven with real exports once Figma's reachable again; see the two `KNOWN GAP` comments in `Icons.tsx`.
- ~~**TextBlock's `variant="L"` doesn't produce "Headline L".**~~ **Resolved** — this entry itself already documented the gap recurring twice (Mode selection, Guided Reflection – Intro) before a spec-conformance review found it a 3rd and 4th time (Concept Questions – Intro, Free Recall Challenge – Intro), all four bypassing `TextBlock` with a hand-styled `<h1>` at `--typography-scale-headline-l-*` directly. A prior version of this entry deferred fixing it to "a third time," which directly contradicted this file's own header rule (fix it on the *second* occurrence); corrected per direct instruction. `TextBlock.module.css`'s `.variantL .title` now points at `typography-scale-headline-l` (33px) instead of `typography-scale-headline-xl` (44px), and all four screens now render a real `<TextBlock variant="L" showCaption={false}>` instead of their own inline heading. **Disclosed regression, not fixed here:** `TextBlock`'s `title` always renders as a `<p>`, never a heading tag — these four screens lose their `<h1>` in the swap. Worth a follow-up on `TextBlock` itself if that matters for this prototype's accessibility bar.
- **`dots-vertical` icon didn't exist.** Needed for the Guided Reflection session flow's AppBar (the right-side overflow-menu icon, confirmed present in Figma for Launched/Recording/Summary/Summary-Continue). Built directly in `Icons.tsx` — a plain 3-dot vertical glyph, unambiguous enough to build with high confidence despite Figma being disconnected (unlike the placeholder icons logged above, which needed real guesswork).
- **MascotBubble had the same hardcoded-expression problem as MascotSlot before it.** Hardcoded to a bespoke `public/images/mascot-approving.png` asset, no `expression` prop. The Guided Reflection session flow's Processing screen needs it showing "thinking", not "approving". This is the same underlying issue already fixed once for `MascotSlot` (see below) — fixed the same way immediately rather than waiting for a literal second occurrence of *this* component's gap, since it's clearly the same architectural pattern. Added a real `expression` prop (default `"approving"`, keeping the original bespoke asset for that one value); any other expression falls back to the shared `public/images/expressions/*.png` family, same convention as `MascotSlot` — those are a different crop/composition than the bespoke approving art, a disclosed fidelity gap for every expression except the default. Story added (`Thinking`).
- ~~**MascotSlot showing an expression other than "standby".**~~ **Resolved** — showed up a second time (**Mode selection**, needing `excited` same as Guided Reflection – Intro before it), so per this file's own rule it got built properly instead of inlined again: `MascotSlot` (`src/components/MascotSlot/MascotSlot.tsx`) now takes a real `expression` prop (default `"standby"`, same 15 values as `Expressions`), with a story (`MascotSlot.stories.tsx`, `Excited` story added). One side effect worth knowing: the default asset changed from the old one-off `public/images/mascot-standby.png` to `public/images/expressions/standby.png` — same artwork (verified by eye), just consolidated onto the one asset family instead of two near-duplicate files.

- **Study plan – home (active-plan build)**: several pieces have no matching Storybook component, all built inline from tokens in `src/app/study-plan/page.tsx`/`page.module.css`: the hero's bordered exam-badge square, the "Maths Exam" title + chevron, the stats row, the Plan/Materials tab pair, and the "Algebraic Fractions 1" header pill. The lesson-step circular nodes reuse the exact done/current/locked badge pattern from the (now-superseded) empty-state build above, just re-themed accent-1 (green) instead of accent-brand (purple) — same "step in a path" idea, different accent per what each reference screenshot actually shows. Two new hand-built placeholder icons (`CalendarIcon`, `ExamIcon` — a checkmark, redrawn once already after a first draft read ambiguously as a "<>" bracket at this size) since no calendar or exam glyph exists in this project's icon set and Figma's Desktop Bridge was disconnected for this build. Flag any of these for promotion to a real component if the same shape is needed by a second screen.
- **`Screen`'s `min-height: 100dvh` doesn't clamp content to the viewport** — fine for every earlier screen since their content happened to fit, but **Study plan – home**'s content (hero + tabs + a 4-step lesson list) is the first to exceed one viewport, so `.middleContent`'s `flex: 1` had nothing to shrink against and the whole page grew past 844px, pushing the bottom nav bar off-screen (caught via a Playwright functional test, not visually — the screenshot alone didn't show it was cut off). Fixed page-locally: `Screen`'s `className` prop now takes a page override (`.screen { height: 100dvh; }` in that page's own module) plus `.middleContent { min-height: 0; overflow-y: auto; }`, so the middle content scrolls internally while the top bar and bottom nav stay pinned in view. Not promoted into `Screen` itself since no other screen needs it yet — flag if a second screen hits the same overflow.
- **The bottom nav bar's 3rd tab (`target-04`, the multi-tone "colored icon family" version) was never actually a valid choice for `NavigationButton`**, which forces every icon's fill to `currentColor` for its Active/Inactive states — correct for its other three icons (`myai-chat`/`search-md`/`trophy-02`, all single-tone) but not for a two-tone illustrated icon, which collapsed into an unrecognizable flat blob once actually set to Active (never caught before now because that tab had no route and was never wired active). Fixed by building `target-01`, a proper single-tone bullseye matching the other three nav icons' own construction, and swapping all three nav-bar usages (`src/app/page.tsx`, `src/app/recall-exercice/page.tsx`, `src/app/study-plan/page.tsx`) to it. `target-04` itself is untouched and still available for any real "colored icon family" use.
- **No redo glyph exists anywhere in this project's icon set or Figma's own library.** Needed for every mode's Recording/Processing "Redo" `ButtonIcon` (was reusing `trash-02`/`trash-01` as a stand-in). Per direct instruction, built as `Redo01` in `Icons.tsx` — but sourced from the `@mdi/react` + `@mdi/js` Material Design Icons npm package instead of a hand-drawn SVG, the one real exception to every other icon in that file being hand-built to match Figma exactly. `size="100%"` (not a fixed px value) keeps it compatible with `IconSlot`'s own sizing system. Same fix also repositioned every Recording/Processing screen's controls row (`Redo` now sits immediately left of `Send`, with an invisible mirrored spacer column keeping `Send`/the mic button pinned to the row's true center regardless of `Redo`'s width) — confirmed pixel-identical between Recording and Processing via a bounding-box check, and confirmed the invisible spacer doesn't leak into the accessibility tree.
